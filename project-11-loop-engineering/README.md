# Project 11: Build the Two-Routine gate (A3 + A4 + A6 Lesson)

Two routines, one wall between them. Routine A drafts work and stops.
Routine B executes the draft — but **only when a human fires it over
HTTP**. Nothing runs on a timer. The decision is a person's.

## What is A3 (API Trigger)?

An API trigger: an HTTP endpoint that starts a routine.

- The routine exposes `POST /execute` and sits idle
- It runs **only** when a request arrives — no schedule, no cron
- Contrast:
  - *One-off invoke*: human types a command (how Routine A runs)
  - *Schedule*: clock decides (`0 9 * * *`) — banned in this project
  - *API trigger*: a network call decides — used by Routine B

## What is A4 (Human Gate)?

A human gate: a checkpoint where a person's decision controls whether
the next step happens.

- Routine A produces `draft_pending.json`, status `PENDING APPROVAL`
- Routine B refuses to act unless **both** are true:
  1. A valid bearer token arrives on the request (only you have it)
  2. The draft status is exactly `PENDING APPROVAL`
- Your `curl` command IS the approval signature
- Doing nothing = rejecting; the draft simply never executes

## What is A6 (Checklist Before Production)?

A6: run a pre-flight checklist before wiring automation to real
systems. See the completed checklist at the bottom of this README.

## The Two Routines

| Routine | File | Trigger | Behavior |
|---|---|---|---|
| A — Drafter | `routine_a_draft.py` | One-off manual invoke | Writes `draft_pending.json` (`PENDING APPROVAL`), prints review instructions, exits |
| B — Executor | `routine_b_execute.py` | **API trigger only** (`POST /execute`) | Verifies bearer token + draft status, performs tasks, logs to `approval_log.md` |

## Setup

1. Bearer token lives in `.env` as `BEARER_TOKEN=...`
   (gitignored — secrets never ride with Git)
2. Start Routine B once; it listens on `127.0.0.1:8011` and waits:

   ```
   python routine_b_execute.py
   ```

3. Run Routine A to mint the draft:

   ```
   python routine_a_draft.py
   ```

## Demonstration

### RUN 1 — one-off invoke of Routine A (no schedule)

```
python routine_a_draft.py
```

Output: draft created → `STATUS: PENDING APPROVAL` → task list →
approval instructions with the exact curl command. Routine A then
exits. It cannot execute anything.

### RUN 2 — human fires Routine B via curl

```
curl -X POST http://127.0.0.1:8011/execute \
     -H "Authorization: Bearer <token-from-.env>"
```

Output: gate opens → tasks executed → draft flipped to `EXECUTED` →
entry appended to `approval_log.md`.

### PROOF: B only ran because the user fired it

- Before the curl call, the server printed *"idle... waiting for a
  HUMAN"* and `approval_log.md` was untouched
- Firing with a wrong token → `401 unauthorized` (no execution)
- Firing again after success → `409` (status no longer
  `PENDING APPROVAL`; the gate closed behind itself)
- No timer exists anywhere in the code: `grep -i schedule *.py` finds
  nothing. B physically cannot start without your HTTP request.

## A6 Checklist Before Production — Completed

- [x] Secrets in `.env` / environment, never in Git (`.gitignore` covers `.env`)
- [x] Bearer token required and compared constant-time (401 on failure)
- [x] Draft status checked before any side effect (409 otherwise)
- [x] Idempotence: status flips to `EXECUTED`; replay gets rejected
- [x] Server binds loopback `127.0.0.1` only — not exposed publicly
- [x] Tokens never logged raw — only sha256 fingerprint
- [x] Every execution appended to `approval_log.md` with timestamp, client IP, trigger type
- [x] No schedules anywhere — both triggers are explicit (invoke / API)
- [ ] Before real deployment: HTTPS reverse proxy, per-user tokens,
